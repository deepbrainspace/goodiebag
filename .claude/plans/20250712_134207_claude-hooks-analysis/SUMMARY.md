# Claude Code Hooks Integration - Executive Summary

## Key Finding: Two Separate Hook Systems

**Critical Understanding**: Claude Code hooks are NOT embedded inside Husky
hooks. They are completely independent systems that operate at different levels:

- **Husky Hooks**: Git-level automation (when git commands execute)
- **Claude Code Hooks**: Claude-level automation (when Claude uses tools)

## How Claude Hooks Work

### Trigger Points

Claude hooks execute when **Claude** performs actions:

- **PreToolUse**: Before Claude runs `git commit`, `gh pr create`, etc.
- **PostToolUse**: After Claude completes file edits, commands, etc.
- **Stop**: When Claude finishes responding to you

### Integration with Your Workflow

```bash
# Example: When Claude creates a PR
1. You ask: "Create a PR for this work"
2. Claude starts: gh pr create --title "feat(pkg): description"
3. → Claude PostToolUse hook triggers
4. → Hook script enhances PR description automatically
5. → PR created with enhanced content
6. → Hook starts background CI monitoring
7. → You get desktop notification when CI completes
```

## Implementation Strategy

### Safety-First Approach

1. **Gradual rollout**: One hook at a time
2. **Non-blocking**: Hooks never prevent your workflow
3. **Easy disable**: Simple off switch for any problematic hook
4. **Extensive logging**: Debug any issues quickly

### Configuration Location

- **Personal**: `~/.claude/settings.json` (your preferences)
- **Project**: `packages/claude-config/hooks/` (team shared)
- **Scripts**: `~/.claude/scripts/` (hook implementations)

### No Conflicts with Existing Tools

- **Husky**: Continues operating at git level
- **GitHub Actions**: Unchanged CI/CD pipeline
- **NX**: Enhanced with better suggestions
- **Manual workflow**: Always available as fallback
