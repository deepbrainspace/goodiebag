# Claude Code Hook Types Reference

## Complete Hook Type Reference

### PreToolUse Hook

**Trigger**: Before Claude executes any tool **Purpose**: Validation,
preparation, permission checking **Control**: Can block tool execution by
returning non-zero exit code

#### Common Use Cases

- Validate file permissions before edits
- Check git repository state before commits
- Analyze context before destructive operations
- Prepare environment for tool execution

#### Example Configuration

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": {
          "tool_name": "Edit",
          "file_paths": ["src/**/*.ts"]
        },
        "hooks": [
          {
            "type": "command",
            "command": "validate-typescript-edit.sh"
          }
        ]
      }
    ]
  }
}
```

#### Example Script

```bash
#!/bin/bash
# validate-typescript-edit.sh

INPUT=$(cat)
FILE_PATH=$(echo "$INPUT" | jq -r '.tool_input.file_path')

# Check if file is in a protected directory
if echo "$FILE_PATH" | grep -q "node_modules"; then
  echo "❌ Cannot edit files in node_modules"
  exit 1  # Block the operation
fi

echo "✅ TypeScript edit validation passed"
exit 0  # Allow operation to proceed
```

### PostToolUse Hook

**Trigger**: After Claude successfully completes tool usage **Purpose**:
Enhancement, automation, follow-up actions **Control**: Cannot block (operation
already completed)

#### Common Use Cases

- Enhance PR descriptions after creation
- Start background monitoring after deployments
- Auto-format code after edits
- Update documentation after changes
- Send notifications after important operations

#### Example Configuration

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": {
          "tool_name": "Bash",
          "command_pattern": "gh pr create.*"
        },
        "hooks": [
          {
            "type": "command",
            "command": "enhance-pr-and-monitor.sh",
            "continue_on_error": true
          }
        ]
      }
    ]
  }
}
```

#### Example Script

```bash
#!/bin/bash
# enhance-pr-and-monitor.sh

INPUT=$(cat)
COMMAND=$(echo "$INPUT" | jq -r '.tool_input.command')

# Extract PR number from command output
PR_NUMBER=$(echo "$COMMAND" | grep -o 'pull/[0-9]*' | cut -d'/' -f2)

if [ -n "$PR_NUMBER" ]; then
  echo "🔄 Enhancing PR #$PR_NUMBER..."

  # Enhance PR description
  AFFECTED=$(nx affected:libs --base=main --plain)
  ENHANCEMENT="

## Automated Analysis
**Affected Packages**: $AFFECTED
**Files Changed**: $(git diff --name-only main...HEAD | wc -l)

Generated by Claude Code hooks 🤖"

  # Update PR description
  gh pr edit $PR_NUMBER --body-file <(gh pr view $PR_NUMBER --json body --jq '.body'; echo "$ENHANCEMENT")

  # Start background CI monitoring
  nohup ./monitor-ci.sh $PR_NUMBER > /dev/null 2>&1 &

  echo "✅ PR enhanced and monitoring started"
fi
```

### Notification Hook

**Trigger**: When Claude needs user attention or input is idle **Purpose**:
Alerts, status updates, reminders **Control**: Informational only

#### Common Use Cases

- Alert when long operations complete
- Notify about important status changes
- Remind about pending actions
- Provide progress updates

#### Example Configuration

```json
{
  "hooks": {
    "Notification": [
      {
        "matcher": { "notification_type": "idle_timeout" },
        "hooks": [
          {
            "type": "command",
            "command": "check-pending-work.sh",
            "continue_on_error": true
          }
        ]
      }
    ]
  }
}
```

#### Example Script

```bash
#!/bin/bash
# check-pending-work.sh

# Check for uncommitted changes
if ! git diff --quiet || ! git diff --cached --quiet; then
  notify-send "Claude Code" "You have uncommitted changes" --urgency=low
fi

# Check for unmerged branches
UNMERGED=$(git branch --no-merged main | wc -l)
if [ "$UNMERGED" -gt 0 ]; then
  notify-send "Claude Code" "$UNMERGED unmerged branches detected" --urgency=low
fi
```

### Stop Hook

**Trigger**: When Claude finishes responding to user **Purpose**: Cleanup,
status reporting, preparation for next task **Control**: Post-response only

#### Common Use Cases

- Suggest workflow improvements
- Report status of ongoing operations
- Prepare environment for next tasks
- Cleanup temporary resources

#### Example Configuration

```json
{
  "hooks": {
    "Stop": [
      {
        "matcher": {},
        "hooks": [
          {
            "type": "command",
            "command": "workflow-status-report.sh",
            "continue_on_error": true
          }
        ]
      }
    ]
  }
}
```

#### Example Script

```bash
#!/bin/bash
# workflow-status-report.sh

echo "📊 Workflow Status Report:"

# Check current branch status
CURRENT_BRANCH=$(git rev-parse --abbrev-ref HEAD)
if [ "$CURRENT_BRANCH" != "main" ]; then
  AHEAD=$(git rev-list --count main..$CURRENT_BRANCH 2>/dev/null || echo "0")
  if [ "$AHEAD" -gt 0 ]; then
    echo "   🔄 Branch '$CURRENT_BRANCH' has $AHEAD commits ready for PR"
  else
    echo "   ✅ Branch '$CURRENT_BRANCH' is in sync with main"
  fi
fi

# Check for running CI
if command -v gh &> /dev/null; then
  OPEN_PRS=$(gh pr list --state=open --json number --jq '.[].number' | wc -l)
  if [ "$OPEN_PRS" -gt 0 ]; then
    echo "   📝 $OPEN_PRS open PR(s) - checking CI status..."
  fi
fi
```

### SubagentStop Hook

**Trigger**: When a Claude subagent completes its task **Purpose**: Coordination
between different Claude agents **Control**: Inter-agent coordination

#### Common Use Cases

- Aggregate results from parallel operations
- Coordinate complex multi-step workflows
- Synchronize shared resources
- Report completion of delegated tasks

#### Example Configuration

```json
{
  "hooks": {
    "SubagentStop": [
      {
        "matcher": { "subagent_task": "code_review" },
        "hooks": [
          {
            "type": "command",
            "command": "aggregate-review-results.sh",
            "continue_on_error": true
          }
        ]
      }
    ]
  }
}
```

### PreCompact Hook

**Trigger**: Before Claude compacts context due to length limits **Purpose**:
Preserve important information before compaction **Control**: Information
preservation

#### Common Use Cases

- Save important context to external files
- Create summaries of work completed
- Preserve state for context restoration
- Log important decisions and rationale

#### Example Configuration

```json
{
  "hooks": {
    "PreCompact": [
      {
        "matcher": {},
        "hooks": [
          {
            "type": "command",
            "command": "preserve-context.sh",
            "continue_on_error": true
          }
        ]
      }
    ]
  }
}
```

#### Example Script

```bash
#!/bin/bash
# preserve-context.sh

INPUT=$(cat)
TIMESTAMP=$(date '+%Y%m%d_%H%M%S')

# Create context preservation file
CONTEXT_FILE="$HOME/.claude/context-archive/session-$TIMESTAMP.md"
mkdir -p "$(dirname "$CONTEXT_FILE")"

echo "# Context Archive - $TIMESTAMP" > "$CONTEXT_FILE"
echo "" >> "$CONTEXT_FILE"

# Save git status
echo "## Git Status" >> "$CONTEXT_FILE"
git status --porcelain >> "$CONTEXT_FILE"
echo "" >> "$CONTEXT_FILE"

# Save recent commits
echo "## Recent Commits" >> "$CONTEXT_FILE"
git log --oneline -10 >> "$CONTEXT_FILE"
echo "" >> "$CONTEXT_FILE"

# Save current branch info
echo "## Branch Information" >> "$CONTEXT_FILE"
echo "Current branch: $(git rev-parse --abbrev-ref HEAD)" >> "$CONTEXT_FILE"
echo "Ahead of main: $(git rev-list --count main..HEAD 2>/dev/null || echo '0')" >> "$CONTEXT_FILE"

echo "💾 Context preserved to $CONTEXT_FILE"
```

## Matcher Patterns

### Tool Name Matching

```json
{
  "tool_name": "Bash", // Exact tool name
  "tool_name": ["Bash", "Edit"] // Multiple tools
}
```

### Command Pattern Matching

```json
{
  "command_pattern": "git commit.*", // Regex pattern
  "command_pattern": "^nx (build|test)" // Complex regex
}
```

### File Path Matching

```json
{
  "file_paths": ["*.py"], // Simple glob
  "file_paths": ["src/**/*.ts"], // Recursive glob
  "file_paths": ["!node_modules/**"] // Exclusion pattern
}
```

### Working Directory Matching

```json
{
  "working_directory": "/specific/path", // Exact path
  "working_directory_pattern": ".*/src/.*" // Regex pattern
}
```

### Combined Matchers

```json
{
  "matcher": {
    "tool_name": "Edit",
    "file_paths": ["packages/**/*.ts"],
    "working_directory_pattern": ".*/goodiebag/.*"
  }
}
```

## Hook Execution Context

### Environment Variables

Hooks automatically receive:

- `CLAUDE_HOOK_TYPE`: The type of hook being executed
- `CLAUDE_WORKING_DIR`: Current working directory
- `CLAUDE_FILE_PATHS`: File paths involved (for Edit tool)
- Custom variables from hook configuration

### Input JSON Schema

```json
{
  "tool_name": "string",
  "tool_input": {
    "command": "string (for Bash)",
    "file_path": "string (for Edit)",
    "description": "string (optional)"
  },
  "working_directory": "string",
  "timestamp": "ISO 8601 string",
  "hook_type": "PreToolUse|PostToolUse|etc"
}
```

### Output Options

1. **Exit Code 0**: Success, continue normally
2. **Exit Code 1**: Error/block (PreToolUse only)
3. **Exit Code 2**: Warning, continue with caution
4. **JSON Output**: Structured feedback to Claude

## Performance and Safety Guidelines

### Performance Best Practices

1. **Keep Scripts Fast**: Target <1 second execution
2. **Use Background Jobs**: For long operations (`&` or `nohup`)
3. **Cache Expensive Operations**: Store results for reuse
4. **Optimize File Operations**: Minimize disk I/O

### Safety Recommendations

1. **Always Use `continue_on_error: true`** for non-critical hooks
2. **Set Reasonable Timeouts**: Default 10 seconds, adjust as needed
3. **Validate All Inputs**: Never trust hook input data
4. **Log Extensively**: Debug issues with comprehensive logging

### Example Safe Hook Configuration

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": { "tool_name": "Bash" },
        "hooks": [
          {
            "type": "command",
            "command": "timeout 10s safe-hook.sh 2>&1 | tee -a ~/.claude/hook.log || echo 'Hook failed safely'",
            "continue_on_error": true
          }
        ]
      }
    ]
  }
}
```
